01

先把日子打开。

当前通过邀请安排试用，尚无公开安装包。申请被收到，不代表已经获得名额或邀请。

  1. 还没有安装包：回官网“下载与试用”提交私密申请。收到邀请后，使用邀请提供的包和校验清单。
  2. 核对版本与文件校验值，打开 DMG 或解压 ZIP，将“日子.app”拖入“应用程序（Applications）”，再从那里打开。App 自带运行环境，无需安装 Node.js。
  3. 这个预览包只有临时签名，尚未获 Apple 公证。按随包安装说明核对来源，再处理系统提示；不要关闭系统整体安全保护。若提示文件损坏或有恶意内容，先停下并保留提示。
  4. 已有旧版时，先正常退出，并按随包说明成套备份旧 App、完整 App 数据和外置成果工作区，再替换。

02

选好这次一起做事的模型。

打开“设置 → 模型”，或点击“模型待配置”。也可从“更多 → 完成第一份成果”找到“打开模型设置”。

  1. 首次没有配置时填写表单；已有配置时，点“添加模型配置”。服务商、模型编号和接口信息以你自己的服务为准。
  2. 点“保存配置”。到“默认模型”确认“对话”使用这份配置，或“对话”沿用“交办默认”且“交办”已经选中它。只有改动默认选择时，才点“保存默认选择并继续待办”。
  3. 连接测试是可选的。需要单独核对连接时，点“测试连接…”并确认“发送测试请求（可能产生费用）”。本机免密服务可留空密钥。

表单里这几项怎么填

配置名称
起一个自己能认出的名字，如“我的研究模型”。
服务商 / 模型编号
使用提供方给出的服务与完整模型 ID。
API 地址
内置服务商默认地址可留空；自定义兼容服务填完整地址，并核对“高级设置 → 兼容协议”。
API Key
填你自己的密钥；只在 App 模型设置里填写，勿粘贴到官网反馈。

保存配置不代表连接已验证。主动测试和研究任务都可能产生所选服务的费用；更改默认模型也可能恢复此前等待配置的已交办任务。

03

给它一件有答案可核对的小事。

练习任务：为一场读书交换会建议活动时段与准备事项。下面两段是明确标注的虚构材料，可以一起作为一份资料导入；没有私人信息，也不是用户访谈。

  1. 在“对话”点“新话题”，再点输入框下方的“研究资料”。也可从“更多 → 完成第一份成果 → 打开研究资料”进入。
  2. 将“资料标题”填为“读书交换会”，把下面的资料粘贴到“资料正文”，点“导入当前话题”。确认它出现在“这个话题的资料”中。
  3. 将问题粘贴到“研究问题”，把“新成果语言”选为“简体中文”。核对材料与问题后，点“不用 Mod 开始研究”。这是本次实际发起模型任务的动作。

04

“说做完了”和“留下成果”是两回事。

等原话题出现实际成果卡，再点“预览”；也可到“成果”页找到这份报告。一句完成回复不能代替保存回执。

  1. 检查建议的时段是否落在周六 14:00–16:00 内，并照顾两位 15:30 要离开的人；准备事项应当具体，不编造额外报名或场地信息。
  2. 展开“核对引用原文”，用“定位段落”查看引用的原文；也可从研究资料列表点“阅读原文”。至少核对两条依据。
  3. 把新增的建议与原文事实分开：例如，提前结束留缓冲是建议，不是原文已经规定的结束时间。未知内容应列为待确认。
  4. 点“导出这一版 Markdown”，打开实际下载文件，确认里面有内容和引用。留好这一版，稍后比较。

不满意也可以停在这里。记下哪条结论没有依据，或哪一步没能完成；不要为了完成指南而把一条回复当成可用成果。

05

把这一版，留给下一次。

这次先试手工修订，看看自己的判断能否留在同一份成果里。它不需要额外模型请求。

  1. 打开报告，点“修订结论”。找到关于活动时段的一条结论，按下方建议修改“结论内容”，将“分类”设为“推断”，填写“这次为什么修改”，再点“保存修订版”。已有引文会保留，请重新核对它们是否支持新说法。
  2. 确认出现新版本，再用“版本 → 预览这一版”查看原来的 v1。新版本不应把 v1 覆盖。若报告没有可修订的结论，就记录这个阻塞，不把新开一份报告当作同份续改。
  3. 等任务结束，通过“日子 → 退出”正常退出，再打开同一个 App。回到原话题与“成果”，分别打开新版和 v1。
  4. 有了这次记录，下次可以在原话题继续提出新问题；需要模型继续修改时，明确说要修订同一份成果，并再次核对保存回执。

修改原因：把时间安排说具体，给提前离场的人留出缓冲；将建议与已知事实分开。

重开仍使用原来的数据位置。不要清空数据、另建 profile 或用第二份新安装来代替本次“接着用”。

06

采用、不采用，都有用。

最有价值的反馈，是你本来想做什么，以及哪里真的帮到你或让你卡住。没有完成也可以提交。

  1. 选一个实际结果：采用 / 修改后采用 / 不采用 / 尚未完成。不要为了支持日子而选“采用”。
  2. 复制下面的反馈模板，在自己的记录里补全。回官网心愿池选“使用体验”或“遇到问题”，填写后再提交；默认私密，选择公开的内容仍需审核。
  3. 如果报错，只填写检查过的提示文字、发生步骤和是否已经出现成果。不要附 API Key、配对码、私人原文、数据库或未经检查的完整日志。

保存模型配置失败+

重新核对字段。新输入的密钥提交后会清空；需要重填时，只在 App 的模型设置里操作。

配置已保存，却还没跑通+

保存不等于连通测试。先检查默认模型与服务地址；若主动测试失败，按具体提示处理，不连续盲目重试。

提交后结果尚未确认+

回原话题检查消息、任务和成果。看到“重新读取更新”时，先用它读取状态；不要另建相同话题再发一次。

已保存成果，但回复失败+

先打开成果确认内容。保存的报告可能已经可用，不需要因为说明文字失败而再执行同一任务。

重开后找不到成果+

先确认还是同一个 App、话题与数据位置。保留现状并反馈，不以清空数据来修复。
