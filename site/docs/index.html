02

从长期对话里，带来重要记忆

你决定哪些内容值得留下。日子先把外部 Agent 的输出当作候选，核对并确认后才加入现有记忆。

  1. 请原 Agent 整理

    在普通话题打开“记忆管理 → 从其他 AI 导入记忆”，复制整理提示，发给原来的长期对话 Agent。先自己检查它给出的内容；日子不会登录来源账号或自动读取全部聊天。

  2. 把规范 JSON 带回来

    粘贴完整 JSON（也可包含 Markdown 代码围栏），或选择 JSON 文件，点“预览候选记忆”。首版不直接解析任意聊天全文、平台压缩包或账号导出。预览本身不保存记忆。

  3. 核对，再选择

    逐条核对正文、来源原话、角色、时间与引用。正文和类型可以编辑；来源只读。候选默认未勾选、仅当前话题；需要同一伙伴的其他话题使用时，再明确改范围。事实和经历还要核对是否到期。

  4. 确认并回看

    勾选想留下的条目，再点“确认导入选中记忆”。保存后在生活事实或工作偏好里管理，也可展开“查看已保存的导入来源”。界面换语言不会翻译原文。

工作偏好
办事方式，例如报告先给结论。
生活事实
当前情况，例如最近固定的工作安排。
过去经历
来源所描述的往事，不等于当前伙伴亲历过。

Agent 总结应标为 assistant，只有真实用户原话才标为 user；找不到原话就用 unknown 和 null，不补造引文或时间。来源引用只是说明文字，不会自动打开或下载。

给导出工具或 Mod 作者

type 支持 work-preference、life-fact、life-experience。role 支持 user、assistant、unknown；只有 unknown 可搭配 null quote。at 是毫秒时间戳或 null，reference 是说明文字或 null。再次导出时保留稳定的 source.id 和条目 id。最多 200 条、UTF-8 256 KiB，每条正文最多 300 个字符。

有些保存成功，有些失败

按页面分别核对结果。失败条目的编辑会保留；尚未收到确认回执时，使用该条的“重试并核对”继续原请求，不要另建一遍。

再次导入同一份内容

同源条目会提示已经导入或内容冲突，不静默覆盖。需要更正时，去已有记忆更新；这不是自动语义去重或矛盾判断。

停用、忘记与导出有什么区别

停用后不再用于新请求，正文与历史仍在。忘记需要先预览影响并确认，会清理日子维护的可追踪副本并阻断同源旧包；原 Agent 对话、独立聊天历史、已完成成果和你另存的文件不会随之消失，已经发出的内容也无法撤回。改过来源 ID 的副本不保证能被识别。

准备换话题或搬迁运行端

切换话题、世界或身份会清空尚未确认的导入草稿。现有 v1 记忆备份将外部 Agent 依据记为 unknown；完整来源留在当前实例，跨实例搬迁时请另行保管原候选包。

03

用 Mod，准备这一次怎么做

Mod 是可以选择的工作方式：把要求变成一张需要你核对的开工卡，再交给原有的任务流程执行。

  1. 先看是否可用

    在“扩展 → 插件”查看工作方式。开启与授权是两个动作；“尚未开启”需要先开启，“尚未授权”则需核对并授予对应权限。出现在列表里不表示已经可执行。

  2. 为这次任务选择

    在原话题点“准备任务”，选择一个 Mod，再点“准备开工卡”。填写重点、受众等必填项，核对资料与选中的记忆；也可以明确选择不用 Mod。

  3. 确认交办，查看实际结果

    准备和修改开工卡不会请求模型；“确认并交办”之后的执行可能产生所选模型费用。回到原话题查看任务与保存成果，收到请求或一句完成回复都不等于成果已经保存。

所选 Mod 更新、停用、撤权，或相关记忆、资料和身份变化后，旧卡可能需要重新准备。不要把过期卡重复提交当作恢复；先查看原任务回执。

想做自己的工作方式？

一个表单 Mod 包含清单和处理函数。清单声明稳定 ID、版本、task.prepare 钩子、适用 task/research 类型与权限；处理函数提供双语标题、说明和最多六个字段，不替用户改问题、资料或记忆。先在独立开发环境检查包，再实际准备一张卡。

只安装信任的本机插件：它们能运行代码，并不是恶意代码沙箱。表单本身不授予文件、网络或设备操作权限。身份、授权、保存回执与历史由宿主管理。

记忆搬家 Mod 可以把获准整理的材料生成同样的候选 JSON 成果。它仍要回到上面的预览与本人确认流程；保存一个成果不等于获得写入记忆的权限。

在已绑定的飞书等渠道里

支持相应指令的渠道可用 /mods 查看工作方式，再按机器人给出的 /task plugin/hook -- 要求准备任务；/say 要求表示本次不用 Mod。只查看列表不会执行任务。渠道需要另外配置和绑定，不能据此推定微信已支持同一套命令。

04

在手机上，接着同一份工作

个人 Server 是保存资料并执行任务的运行端；手机网页或 PWA 是通向它的入口。先服务一个主人自己的设备，不是多人托管平台。

  1. 先有自己的运行端

    使用受邀提供的个人 Server，或由操作者从已获授权的源码候选搭建。运行端需配置自己的模型并保持可达；手机网页不是独立的离线执行器。

  2. 在新设备完成配对

    从可信的 HTTPS 地址打开配对页。让运行端操作者现场生成短期配对码，输入后回到页面。不要公开转发配对码；它在有效窗口内可重复使用。

  3. 打开同一话题

    查看已经保存的对话、记忆与成果，再继续同一件事。系统提供“安装”或“添加到主屏幕”时可以使用；具体入口取决于浏览器与系统，不是下载 Android APK。

  4. 离线或设备遗失时

    离线页不执行任务，也不替你后台重试写入。恢复网络后先查看原任务状态与回执。设备不再使用时，让运行端操作者撤销授权；备份与迁移则需保全完整的私有运行目录。

对话、记忆、成果、模型配置与授权保存在运行端；手机不会自动获得那台电脑的文件或应用控制权限。网页界面不会缓存私人 API、聊天与成果用于离线阅读。模型任务仍可能把所需内容发送给你配置的提供商。

搭建者需要准备什么

已获授权的源码候选需要 Node.js 22.19+ 和项目依赖。使用独立、私有的空数据目录；个人服务只监听本机回环地址。手机访问需要另外设置可信 HTTPS 代理或隧道，并配置精确来源，不能只在手机输入电脑的 localhost。

完成环境与 HTTPS 设置后，用 personal-server 的 check/start 检查并启动选定目录，再用 pair 生成配对码、clients 查看设备、revoke 撤销设备。同一数据目录只保留一个运行实例；完整备份、认证材料与模型密钥不要放进公开仓库。
