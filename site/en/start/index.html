01

First, open Rizi.

Trials are arranged by invitation. There is no public installer yet. A received request is not a confirmed place or an invitation.

  1. No package yet? Use Download & try Rizi on the product site to send a private request. After an invitation, use the package and checksum list supplied with it.
  2. Check the version and checksum, open the DMG or extract the ZIP, and drag “日子.app” into Applications. Open it from there. The runtime is included; you do not need to install Node.js.
  3. This preview has an ad-hoc signature and has not been notarized by Apple. Verify its source and follow the included installation instructions before handling system prompts. Do not disable system-wide protection. If macOS reports damage or malware, stop and retain the message.
  4. If you already have Rizi installed, quit normally and follow the included backup instructions first. Keep the old app, its complete app data, and external results workspace together before replacing it.
No package yet? Request a trial↗

Use the desktop app for this trial. Remote, Feishu, and Telegram remain experimental. New Web / PWA and Android experiences are not part of this rc.4 guide.

02

Choose the model to work with.

Open Settings → Models, or choose the model configuration prompt. More → Your first saved result also offers Open model settings.

  1. Fill the form if no profile exists, or choose Add model profile. Use the provider, full model ID, and API details for your own service.
  2. Choose Save profile. Under Default models, check that Chat uses this profile, or that Chat uses the task default and Tasks selects this profile. If you change the defaults, choose Save defaults and resume pending tasks.
  3. A connection test is optional. To test separately, choose Test connection… and then Send test request (may incur a charge). A local service that requires no key can leave the key blank.

What goes in the form

Profile name
A name you will recognize, such as “My research model”.
Provider / Model ID
The service and full model ID supplied by your provider.
API URL
Leave blank for a built-in provider’s default endpoint. A custom compatible service needs its complete URL and the correct Advanced settings → API protocol.
API key
Your own key, entered only in the app’s model settings. Never paste it into website feedback.

Saving does not verify a connection. Explicit tests and research tasks can incur provider charges. Changing defaults can also resume previously submitted tasks waiting for configuration.

03

Give it a small, checkable question.

The task: suggest a time slot and preparation tasks for a book swap. The two notes below are explicitly fictional practice material. Import them together as one source; they contain no private information or claimed user research.

  1. In Chat, choose New topic, then Research materials below the message box. More → Your first saved result → Open Research materials is another entry.
  2. Enter “Book swap” as Source title. Paste the material below into Source text and choose Import into this topic. Check it appears under Materials in this topic.
  3. Paste the question into Research question. Choose English under New report language. Review the material and question, then choose Start research without a Mod. This is the action that actually submits a model task.

04

A finished reply is not a saved result.

Wait for an actual result card in the original topic, then choose Preview. You can also find the report in Results. A reply claiming completion does not replace a save receipt.

  1. Check that the suggested slot fits Saturday 14:00–16:00 and accounts for the two people leaving at 15:30. Preparation tasks should be concrete, with no invented registration or venue details.
  2. Expand Check cited sources and use Go to paragraph to read the quoted source. Read source in the materials list is another route. Check at least two claims against their evidence.
  3. Keep recommendations separate from source facts. Finishing a little earlier is a suggestion, not an end time already specified by the notes. Unknowns should remain questions to confirm.
  4. Choose Export this version as Markdown and open the downloaded file. Check that it contains the result and quotations. Keep this version for the comparison.

You can stop here if it is not useful. Record a claim without support or the step you could not finish. A reply does not become useful work just because you want to finish the guide.

How to tell this step worked

05

Leave a place for next time.

Try a manual revision first, so your own judgment stays with the same result. This does not need another model request.

  1. Open the report and choose Revise findings. Find the time-slot finding, edit Finding text using the suggestion below, set Category to Inference, fill Reason for this revision, and choose Save revision. Existing quotations stay in place; check they still support your edited claim.
  2. Check that there is a new version, then use Versions → Preview this version to revisit v1. The new version should not overwrite it. If the report has no editable findings, record that block rather than treating a separate new report as a revision.
  3. Wait for tasks to finish, quit normally using 日子 → Quit, then reopen the same app. Return to the original topic and Results, and open both the latest version and v1.
  4. Next time, continue in the same topic. If you ask the model to revise further, explicitly request a revision of this same result and check the new save receipt again.

Reason: Make the timing concrete, leave a buffer for people departing early, and distinguish a recommendation from known facts.

Reopen with the same data location. Clearing data, creating another profile, or opening a fresh installation does not test continuity with this work.

06

Useful or not, tell us.

The most useful feedback is what you wanted to do and where Rizi helped or got in the way. You can report an unfinished attempt too.

  1. Choose the actual outcome: used / used after changes / not used / not finished. You do not need to choose “used” to support the project.
  2. Copy the template below and fill it in your own notes. On the site, choose Experience or A problem in the wish pool, review your text, and submit. Feedback is private by default; public contributions still require review.
  3. For an error, include only checked error text, the actions you took, and whether a result already appeared. Do not attach API keys, pairing codes, private originals, databases, or unchecked full logs.

If you get stuck, follow the status

Model profile did not save+

Check the fields. Newly entered keys are cleared after submission; re-enter one only in the app’s model settings if needed.

A saved profile has not worked yet+

Saving is not a connection test. Check the selected default and API URL. If you choose to test and it fails, follow the specific message instead of repeatedly retrying.

Receipt is uncertain after submission+

Check the original topic for messages, tasks, and results. If Reload updates is offered, use it to read the status. Do not create an identical new topic and resubmit.

The result saved but the reply failed+

Open the actual result first. It may already be useful; a failed explanation does not require running the same task again.

The result is missing after reopening+

Confirm you opened the same app, topic, and data location. Preserve the current state and report the problem. Do not clear data as a repair step.
